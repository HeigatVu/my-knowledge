# Implementation Plan: Organize the pasted EdrawMind mindmap into Cornell notes

## Overview

Turn the user's pasted EdrawMind outline ("DATA COLLECTION AND PREPROCESSING") into Cornell-format
notes under `AI_ML/07_Data-Collection-and-Preprocessing/`, matching the existing vault convention
(see RESEARCH-2026-09-17.md for the pattern and cross-link targets already confirmed in-tree). The
existing placeholder note is expanded rather than replaced, the full original mindmap text is kept
verbatim in it, and the two large subtrees that don't fit the vault's atomic-note size convention
(feature extraction / word embeddings, and image feature extraction / edge detection) become their
own child notes. The Map of Content is updated to list them.

## Architecture decisions

- One task, not several: this is a single cohesive content change (one branch, one PR) touching a
  small, fixed set of Markdown files with no code, build, or dependency graph between them beyond
  "the child notes link back to the parent note," which is satisfied by writing the parent first.
- Keep the full verbatim mindmap text in exactly one place (`01_Data-Collection-and-Preprocessing.md`)
  rather than duplicating the whole outline into every child note, so "keep my original note" has one
  unambiguous, byte-for-byte source of truth. Child notes quote only their own excerpt for
  self-contained readability and cite the parent as the source of the full text.
- Reuse the existing note's frontmatter/callout skeleton and heading order exactly (Summary → title →
  `## 📌 Original EdrawMind Mindmap & Note` → `---` → What → Why → How), rather than inventing a new
  layout, so the note set stays visually and structurally consistent with the rest of `AI_ML/`.

  oversized file.

  those files' current names; mitigated by confirming each target file exists with `find`/`grep`
  before writing the link (already done in RESEARCH-2026-09-17.md) and re-checking after writing.
