# Spec: Organize the pasted EdrawMind mindmap into Cornell knowledge notes

## Objective

The user maintains a personal Obsidian vault (`my-knowledge`) as a PKM (personal knowledge
management) system. They pasted the full text export of an EdrawMind mindmap titled
"DATA COLLECTION AND PREPROCESSING" into chat and asked for it to be organized into Cornell-style
knowledge notes under `AI_ML/`, using the vault's own
`10_System/Templates/Cornell-Note (Templater).md` template to answer Summary / What is it? / Why is
it important? / How is it related to ...?, cross-linked to the user's existing notes, while
preserving the original mindmap text verbatim (not summarized away).

Users: the vault owner only (single-player PKM, not a product). Success: the pasted mindmap content
exists in the vault as Cornell-formatted note(s) that (a) contain the full original outline text
verbatim, (b) carry a synthesized Summary/What/Why/How per the template, (c) link to related
existing notes already in the vault, and (d) fit the vault's established folder/numbering/frontmatter
conventions instead of introducing a new pattern.

## Tech stack

Not a software project: this is a Markdown/Obsidian content vault (`AI_ML/`, `Neuroscience/`,
`Signal_Processing/`, `Computer_Science/`, `10_System/`). No build system, package manager, app
code, or test runner is present at the workspace root. The only "stack" constraint is Obsidian +
Templater plugin conventions already encoded in existing notes (YAML frontmatter with
`cssclasses: [cornell-left, cornell-border]`, `priority`, `order`, `topic-group`, `gist`,
optional `aliases`; body using `[!summary]`, `[!cue]`, and `[!quote]` Obsidian callouts; `[[wikilink]]`
cross-references; optional Mermaid diagrams).

## Commands

None. There is no build, lint, or test command in this repository (`vibe-agent doctor` confirms no
`vibe-checks.yaml` is configured, so command-based verifier nodes are legitimately skipped).
Verification here is by reading the produced Markdown files and matching them against the template
contract and the vault's existing note conventions.

## Code style

Follow the existing note style exactly, taking
`AI_ML/07_Data-Collection-and-Preprocessing/01_Data-Collection-and-Preprocessing.md` and
`AI_ML/02_Machine-Learning/03_Deep-Learning-Architectures.md` as the pattern to match:
frontmatter → `[!summary]` callout → H1 title → `## 📌 Original EdrawMind Mindmap & Note` with a
fenced ` ```text ` quote block of the verbatim mindmap → `---` → `[!cue] What is it?` →
`[!cue] Why is it important?` → `[!cue] How is it related to ...?` with `[[wikilink]]` bullets.
Numbered filenames (`NN_Title.md`) inside numbered topic folders, `order` in frontmatter matching
file position within its folder.

## Testing strategy

No automated tests apply to a content vault. Manual/self-check verification instead:
- Every new/edited note parses as valid YAML frontmatter + Markdown and opens the four required
  template sections (Summary, What, Why, How).
- The full original pasted mindmap text is present verbatim (byte-for-byte, only reformatted into a
  fenced code block) in at least one note, so nothing from the user's original is lost or paraphrased
  away.
- The existing note `AI_ML/07_Data-Collection-and-Preprocessing/01_Data-Collection-and-Preprocessing.md`
  is expanded, not deleted or replaced with unrelated content ("keeping my original note").
- Every `[[wikilink]]` added resolves to a file that actually exists in the vault (checked with
  `grep`/`find`, not guessed).
- `AI_ML/00_AI-Engineer-MOC.md` lists every new note file under its `07_Data-Collection-and-Preprocessing`
  section.

## Boundaries

- **Always:** preserve the full original pasted mindmap text verbatim somewhere in the note set;
  follow the Cornell template's frontmatter and callout contract; only touch files under `AI_ML/`
  (plus updating the MOC's `07_Data-Collection-and-Preprocessing` bullet list) and this run's own
  `docs/` artifacts; keep commits scoped to this content.
- **Ask first:** restructuring the vault's folder numbering, renaming any existing note, or changing
  the Cornell template file itself.
- **Never:** deleting or overwriting the user's other pre-existing notes; committing the large
  pre-existing untracked `AI_ML/` backlog that is unrelated to this task; merging to `main` without
  the opt-in the workspace already recorded (`merge: false` today, so this run stops at a green pull
  request for the user to merge by hand).

## Data classification

No sensitive data is involved. The mindmap content is the user's own personal study notes on public
ML/NLP concepts (data preprocessing, word embeddings, edge detection). No credentials, personal
data, or internal/proprietary structure appears anywhere in the source text or the produced notes.
